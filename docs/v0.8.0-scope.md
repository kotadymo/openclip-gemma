# OpenVLCLIP v0.8.0 — agreed scope

**Decision date:** 2026-10-23  
**Status (2026-10-24):** Release preparation only. Implementation PR #56 is
merged at `66ae7b650601ae0ca8636e6e218c86ae70b72d72`; v0.8.0 is not tagged,
published to PyPI, or released on GitHub.

## Goals

| Workstream | Target | Status |
| --- | --- | --- |
| SigLIP 2 FixRes expansion | `siglip2-base-384` (768D), `siglip2-large-256` (1024D), `siglip2-so400m-384` (1152D) | Implemented and CPU FP32 parity passed for all three. CUDA BF16 passed for all five SigLIP checkpoints; CUDA FP32 passed for four, with Large-256 unverified due to shared-GPU memory limits. |
| Meta PE-Core | T16-384 and S16-384, exposed via shared image/text API | Optional backend implemented; CPU FP32 parity passed against the pinned timm-converted OpenCLIP weights. CUDA and Meta-original comparisons were not run. |
| Search performance | Preserve exact search and index format; reduce Python candidate sorting with NumPy partition; FAISS remains optional | Correctness matched the prior exact-sort baseline in 54/54 cases. Low-tie workloads improved; all-equal-score workloads regressed, so no universal speedup is claimed. |
| DINOv3 + dino.txt | **Explicitly excluded from v0.8.0** | Deferred; no checkpoint downloads, backend work, Registry entry, release tests, or DINOv3 license/access requirements |
 
The v0.8.0 source Registry contains **10 checkpoints**: the five v0.7.1
models, three SigLIP 2 additions, and two PE-Core variants. The search
optimization adds no model checkpoints.

## Compatibility and minimum release checks

- Maintain the existing five v0.7.1 model APIs and index/EmbeddingSpace compatibility.
- Preserve the three added SigLIP 2 models' independently pinned source revisions, 384/256/384 image sizes and 768/1024/1152 dimensions. CPU FP32 reference comparisons have passed; GPU results and the Large-256 FP32 limitation are recorded in the validation document.
- Preserve PE-Core's separate identity/revision and CPU image/text/logit parity against the same pinned timm-converted OpenCLIP checkpoints. Do not describe this as comparison to Meta's original weights. CUDA was not tested and is not a required condition for this release-preparation task.
- Keep NumPy exact search as the default and preserve score/ranking semantics and existing index storage. Make FAISS or any ANN option strictly optional, with latency/memory and (for ANN) recall comparisons before claiming benefit.
- Reuse normal fast CI and existing Trusted Publishing; avoid creating heavyweight matrix/model-loading jobs or making external benchmark suites mandatory.
- Set the source package version to 0.8.0 for release preparation, but do not create a tag, publish to PyPI, or create a GitHub Release in this task.
- **No DINOv3-related approval, license acceptance, gated weight download, or model parity is part of v0.8.0 completion.** Preserve [the separate DINOv3 research notes](v0.8.0-dinov3-dinotxt-prerequisites.md) only as future background.

## Implementation and release-preparation status

The model backends, optional PE-Core dependency, exact-search optimization,
CPU reference checks, benchmark results, and CUDA results described above are
already merged in PR #56 or recorded in the release-validation documents.
This release-preparation change updates documentation and package metadata,
runs focused regression/lint/lock/build checks, and merges through a normal
pull request. v0.8.0 publication remains a separate operation.
