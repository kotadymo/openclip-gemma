## Objective and constraints

Deliver v0.8.0 with **10 registered checkpoints**: the existing five v0.7.1 models, three SigLIP 2 FixRes additions and two optional PE-Core T/S models; preserve backward compatibility and provide measured exact-search acceleration. **Do not work on DINOv3/dino.txt, FAISS/ANN, training, new model families or unnecessary CI expansion.**

Read, in this order:
1. `docs/v0.8.0-scope.md`
2. `docs/v0.8.0-siglip2-variants.md`
3. `docs/v0.8.0-pe-core.md`
4. `docs/v0.8.0-search-optimization.md`
5. `src/openvlclip/registry.py`, `src/openvlclip/backends/pe_core.py`, `src/openvlclip/backends/siglip2.py`, `src/openvlclip/_ranking.py`, `pyproject.toml`

## Already implemented — do not redo

- SigLIP 2: `siglip2-base-384` (768D), `siglip2-large-256` (1024D), `siglip2-so400m-384` (1152D), pinned revisions, registered in source.
- PE-Core: `pe-core-t16-384` and `pe-core-s16-384`, 512D, optional OpenCLIP-backed loading of pinned *timm converted* weights; registered in source.
- NumPy `select_top_k` with `np.partition` and stable original tie-breaks for image/video exact search.
- Real CPU FP32 parity is recorded for all five additions; mock tests remain the lightweight CI coverage. See `docs/v0.8.0-validation.md`.
- The `pecore` extra is locked to `open-clip-torch>=3.3.0,<3.4.0`; both PE-Core `local-dir:` model and tokenizer paths were exercised with 3.3.0.
- Exact-search correctness and latency were measured across 54 cases. Low-tie cases improved; the synthetic all-equal-score cases regressed and are documented without a universal speedup claim.
- Release preparation sets the source package version to 0.8.0; the latest published PyPI package remains v0.7.1.

## Release-preparation requirements

- Keep the README and changelog clear that PyPI v0.7.1 is still the latest published version, while v0.8.0 source contains ten registered checkpoints.
- Keep `pyproject.toml` and `uv.lock` synchronized at 0.8.0; run only focused regression tests, lint, lock consistency, and a distribution build. Do not add heavy model-loading tests to normal CI.
- Preserve existing model APIs, EmbeddingSpace identities, index formats, pinned revisions, and optional `[pecore]` behavior.
- Record the CUDA limitations without treating Large-256 FP32 or PE-Core CUDA as required gates for this release-preparation task. Do not rerun completed CPU/GPU numerical comparisons.
- Commit and merge release-preparation changes through a normal PR when required CI and review conditions pass.
- Do not create the v0.8.0 tag, publish to PyPI, create a GitHub Release, or modify publishing/Trusted Publishing settings.
