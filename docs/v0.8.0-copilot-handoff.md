## Objective and constraints

Deliver v0.8.0 with **10 registered checkpoints**: the existing five v0.7.1 models, three SigLIP 2 FixRes additions and two optional PE-Core T/S models; preserve backward compatibility and provide measured exact-search acceleration. **Do not work on DINOv3/dino.txt, FAISS/ANN, training, new model families or unnecessary CI expansion.**

## Already implemented — do not redo

- SigLIP 2: `siglip2-base-384` (768D), `siglip2-large-256` (1024D), `siglip2-so400m-384` (1152D), pinned revisions, registered in development source.
- PE-Core: `pe-core-t16-384` and `pe-core-s16-384`, 512D, optional OpenCLIP-backed loading of pinned *timm converted* weights; registered in development source.
- NumPy `select_top_k` with `np.partition` and stable original tie-breaks for image/video exact search.
- Real CPU FP32 parity is recorded for all five additions; mock tests remain the lightweight CI coverage. See `docs/v0.8.0-validation.md`.
- The `pecore` extra is locked to `open-clip-torch>=3.3.0,<3.4.0`; both PE-Core `local-dir:` model and tokenizer paths were exercised with 3.3.0.
- Exact-search correctness and latency were measured across 54 cases. Low-tie cases improved; the synthetic all-equal-score cases regressed and are documented without a universal speedup claim.
- `pyproject.toml` remains at v0.7.1 intentionally.

## Ordered remaining tasks and acceptance criteria

### P0 — establish actual status and unblock optional dependency

- Check current main branch and any open PRs; distinguish merged vs open changes, do not duplicate features.
- Confirm compatible `open-clip-torch` release(s) with the actual `local-dir:` model/tokenizer API, and whether snapshot files load at both immutable revisions; record version(s). Add optional `[pecore]` dependency with **tested and bounded** versions; update lock if required and document `pip install "openvlclip[pecore]"`.
- Keep `import openvlclip` and `list_models()` functional without OpenCLIP installed; creating PE-Core should return a clear actionable error when extra is missing.
- Resolve PE-Core `preprocessing_id` against exact real OpenCLIP transform/config (resize mode, interpolation, crop, normalization, input size), not assumptions or hard-coded labels. If its identity changes, ensure archives/index compatibility does not accidentally accept embeddings generated with another transform.

### P0 — real-weight parity evidence (release blocker)

- SigLIP 2 each of the three pinned official checkpoints: compare OpenVLCLIP vs independently instantiated `transformers.AutoModel`/`AutoProcessor` on identical deterministic samples, including tokenizer/image tensors, raw and normalized image/text embeddings, and model-specific similarity logits with official scale/bias behavior.
- PE-Core both pinned converted checkpoints: compare OpenVLCLIP vs separately constructed OpenCLIP reference *using those same converted weights* for tokenizer IDs, image transform tensors, raw/normalized image/text embeddings, and trained logit-scale outputs; if practical, separately describe (not conflate) any original Meta-model comparison.
- Confirm model-specific native dimensions and input sizes; perform one index build/query per new checkpoint and reject cross-checkpoint EmbeddingSpace reuse.
- Record actual results in a compact `docs/v0.8.0-validation.md` with: checkpoint/revision, libraries and versions, OS/device/dtype, test inputs, max absolute/relative difference or cosine difference, pass threshold chosen in advance, memory limits, commands, and PASS/FAIL/BLOCKED. Avoid logging signed links, credentials or full large outputs.
- Never label mocked outputs as independent parity. If actual weights cannot run, record BLOCKED and do not claim release readiness. For resource-heavy SO400M, a dedicated capable machine/manual run is acceptable. Do not trigger heavy downloads in normal CI.

### P1 — exact search performance and correctness

- Benchmark before/after top-k and total query latency (warm runs and median; fixed inputs and hardware), at 1k, 10k and 100k vectors, dims 512/768/1152 and representative k=5/10/100. Include low-tie and high-tie workloads; report peak memory if practicable.
- Compare full result ordering, scores and tie behavior for image and native-video indexes against prior reference behavior. Keep index storage format and exact retrieval semantics unchanged. Report speedups only if observed; if the optimization regresses commonly used sizes, fix or justify it.
- Place measurements and reproducible command(s) in `docs/v0.8.0-validation.md`. No FAISS/ANN by default.

- Perform lightweight targeted tests for changed backend/registry/ranking/index behavior, one packaging/import smoke test, and existing fast CI. Do not add new OS/Python matrices, heavyweight model-loading CI or external benchmark pipeline unless a demonstrated release-critical issue requires it.
- Bump `pyproject.toml` to 0.8.0 **only when gates are satisfied** and the user has authorized release preparation. Do not create tags, publish PyPI, or alter Trusted Publishing workflows without explicit user approval.
