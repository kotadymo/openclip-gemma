# v0.8.0 PE-Core T/S — opt-in development implementation

Models: `pe-core-t16-384` (`timm/PE-Core-T-16-384`) and `pe-core-s16-384` (`timm/PE-Core-S-16-384`). Both have 384×384 RGB preprocessing, a 32-token text context and 512D global image/text embeddings.

The **checkpoint source is timm's OpenCLIP-converted weights**, not the separately packaged Meta originals. Hugging Face cards mark both as Apache-2.0. OpenCLIP handles the model architecture, tokenizer, trained logit scale and preprocessing, preventing bundling/copying Meta's upstream Python. All user-installed OpenCLIP and other third-party packages retain their own licenses.

The backend uses Hugging Face `snapshot_download` with full immutable commit revisions (`7fe539ed578ac49a1c2b4f946e4b0747704c825a`, `3249a38eb1c432ec19231c6fe1774acb6a4e4efe`) and only downloads necessary safetensors/config/tokenizer files. These full IDs were verified from Hugging Face commit pages. Before publishing, verify the exact official license and processor/config revisions. It uses `open_clip.create_model_and_transforms("local-dir:<snapshot>")` and `open_clip.get_tokenizer("local-dir:<snapshot>")` to avoid floating Hub aliases. Model weights are never bundled.

Installation for development after cloning the repository:

```bash
pip install open-clip-torch
```

Then call `create_model_and_transforms("pe-core-t16-384")` or `create_model_and_transforms("pe-core-s16-384")`, and `get_tokenizer()` as usual. OpenVLCLIP core import and `list_models()` do not need the optional OpenCLIP package.

Capabilities currently **exclude** native video, patch embeddings, and mixed input APIs even though upstream PE has other feature variants. `logit_scale_mode="strict"` uses the trained OpenCLIP scale; `"cosine"` provides unscaled normalized cosine logits.

1. Load **both** pinned converted checkpoints on a real machine. Compare image/text normalized and raw features, tokenizer output, processor tensors and trained-scale logits against separately created OpenCLIP references.
2. Where possible, separately evaluate numerical parity to Meta's original PE-Core weights and code, recording any conversion/preprocessing differences. Do not represent converted weights as the original binary format.
3. Confirm pinned snapshot revisions resolve and the exact open_clip version/API is compatible with supported Python 3.12–3.14. Add a lock-compatible `pecore` optional dependency extra before a formal package release, if appropriate.
4. Verify image-index creation/search and EmbeddingSpace identity for both 512-dimensional models.
5. **Do not claim official real-model parity from fake-model tests or publish v0.8.0 before these checks.**
