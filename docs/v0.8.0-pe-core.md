# v0.8.0 PE-Core T/S — opt-in development implementation

Models: `pe-core-t16-384` (`timm/PE-Core-T-16-384`) and `pe-core-s16-384` (`timm/PE-Core-S-16-384`). Both have 384×384 RGB preprocessing, a 32-token text context and 512D global image/text embeddings.

The **checkpoint source is timm's OpenCLIP-converted weights**, not the separately packaged Meta originals. Hugging Face cards mark both as Apache-2.0. OpenCLIP handles the model architecture, tokenizer, trained logit scale and preprocessing, preventing bundling/copying Meta's upstream Python. All user-installed OpenCLIP and other third-party packages retain their own licenses.

The backend uses Hugging Face `snapshot_download` with full immutable commit revisions (`7fe539ed578ac49a1c2b4f946e4b0747704c825a`, `3249a38eb1c432ec19231c6fe1774acb6a4e4efe`) and only downloads necessary safetensors/config/tokenizer files. Both `local-dir:` model loading and tokenizer construction were run successfully with `open-clip-torch` 3.3.0. It uses those APIs to avoid floating Hub aliases. Model weights are never bundled.

For a source checkout, install the optional extra:

```bash
pip install -e ".[pecore]"
```

The development extra currently bounds `open-clip-torch` to `>=3.3.0,<3.4.0`. For a future published package, the corresponding install command will be `pip install "openvlclip[pecore]"`. Then call `create_model_and_transforms("pe-core-t16-384")` or `create_model_and_transforms("pe-core-s16-384")`, and `get_tokenizer()` as usual. OpenVLCLIP core import and `list_models()` do not need the optional OpenCLIP package.

The pinned snapshots' `open_clip_config.json` files specify `mean/std=[0.5,0.5,0.5]`, bilinear interpolation, and squash resizing at 384×384. The backend checks these values before loading so they cannot silently diverge from its `preprocessing_id`; PIL input is converted to RGB before the OpenCLIP transform.

Capabilities currently **exclude** native video, patch embeddings, and mixed input APIs even though upstream PE has other feature variants. `logit_scale_mode="strict"` uses the trained OpenCLIP scale; `"cosine"` provides unscaled normalized cosine logits.

## Validation status and remaining checks

1. Both pinned converted checkpoints passed CPU FP32 comparisons against independently constructed OpenCLIP references using the same converted weights. Preprocess tensors and tokenizer IDs matched exactly; raw and normalized features, learned scale, and logits had maximum absolute error `0.0` on the deterministic inputs. This does **not** claim parity to Meta's original checkpoint/code.
2. Each checkpoint built and queried an image index. Reusing a T-Core index with the S-Core model's 512-dimensional EmbeddingSpace was rejected.
3. The pinned configs specify 384×384 input, 512D output, context length 32, bilinear squash resize, and mean/std `[0.5,0.5,0.5]`; runtime validation now enforces the preprocessing fields represented by `preprocessing_id`.
4. The `[pecore]` extra is locked to `open-clip-torch>=3.3.0,<3.4.0`; runtime was tested on Python 3.12.10 only. Python 3.13–3.14, CUDA FP32/BF16, and comparison to Meta's original weights remain unverified.
5. **Do not publish v0.8.0 until the remaining release gates are resolved.** See the [validation record](v0.8.0-validation.md).
