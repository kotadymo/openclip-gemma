# DINOv3 + dino.txt — prerequisites for v0.8.0

**Status:** Official API and a named checkpoint are identified. License acceptance, exact artifact provenance and real numerical validation are **not yet complete**. This note does not assert the backend is implemented.

## Confirmed from Meta's official repository

- Source: https://github.com/facebookresearch/dinov3
- Official zero-shot head Hub entrypoint: `dinov3_vitl16_dinotxt_tet1280d20h24l` in `dinov3/hub/dinotxt.py`
- Official method: `torch.hub.load(REPO_DIR, "dinov3_vitl16_dinotxt_tet1280d20h24l", weights=HEAD_CHECKPOINT, backbone_weights=BACKBONE_CHECKPOINT)`
- Default dino.txt adapter weight enum: `DINOTxtWeights.LVTD2300M`
- Default backbone: `dinov3_vitl16`, `BackboneWeights.LVD1689M` (ViT-L/16 distilled).
- Combined dino.txt output dimension: `2048`; vision backbone patch size `16`; text encoder width `1280`, `20` attention heads, `24` blocks; context length `77`. These values are present in the official Hub configuration.
- Required official BPE vocabulary: `https://dl.fbaipublicfiles.com/dinov3/thirdparty/bpe_simple_vocab_16e6.txt.gz` (check linked vocabulary license separately).
- Upstream code **and model weights** are under the DINOv3-specific License, **not Apache-2.0**. The hosted access-form agreement and repository LICENSE.md are **not identical**; see the version comparison below. This is not legal approval to redistribute derivative code or weights.

## License texts and OpenVLCLIP compliance decision (reviewed 2026-10-23)

The user supplied the August 14 access-form terms; their wording was independently matched to Meta's live public access form. Both texts cover Meta's code and model weights and grant conditional use, reproduction, modification, and redistribution rights; neither is Apache-2.0. The access-form terms impose research attribution, sanctions/trade-control restrictions, and prohibited-use restrictions. The two public versions also differ in other phrasing. Do not choose a binding version or assert a blanket legal conclusion solely from the repository's LICENSE.md.

**Conservative distribution policy for v0.8.0:**

1. Keep OpenVLCLIP-owned **independent wrapper code** under the project's existing license; do not copy/publish official DINOv3 source, modified source, tokenizer vocabulary, or model weights without separately verifying and complying with the specific terms that apply to their distribution.
2. Make official DINOv3 an **optional external dependency** with weights sourced directly by an authorized user (or supplied locally) rather than including Meta weights in PyPI wheel/sdist.
3. Include a prominent **"Built with DINOv3"** statement in a relevant public OpenVLCLIP README/product documentation when DINOv3 support is published. Clearly attribute Meta; explain that DINOv3 materials are subject to their **own** license, not the package's default license. For any distribution of DINO Materials/derivatives, also **include the relevant full Agreement** rather than just a link.
4. Credit the DINOv3 work in papers/research reporting results using it.
5. Record which license text was actually accepted when requesting access and which is provided with each obtained artifact. If their obligations conflict or official source/Redistribution status is uncertain, seek Meta/legal clarification **before shipping**; a separate dependency does not itself waive downstream conditions.
6. Do not commit gated download URLs, user account information, license acceptance receipts or raw checkpoints to GitHub.

This is an engineering compliance plan, **not** a legal determination or proof of Meta access approval. Access has not been confirmed and neither backbone nor adapter SHA-256 has been verified.

## Official API inventory (confirmed in upstream source)

The pinned upstream code for numerical reference should use a recorded exact Git SHA, not a floating `main`. The official `DINOTxt` class exposes:
- `encode_image(image, normalize=False)` — global image embedding
- `encode_text(text, normalize=False)` — global text embedding
- `encode_image_with_patch_tokens(image, normalize=False)` — a global feature plus vision-head and backbone patch tokens
- `get_logits(image, text)` — normalized image/text features with learned logit scale
- `forward(image, text)` — global embeddings, scale and patch tokens

These are confirmed **source APIs**, not executed-model parity, and the precise preprocessing/patch similarity-map behavior must be established against downloaded official weights.

## Actions required before implementation / publication

1. **User action:** visit https://ai.meta.com/resources/models-and-libraries/dinov3-downloads/ and review/accept the DINOv3 license as applicable. Meta says accepted users receive an email listing download URLs for backbones and adapters. Do not store credentials, temporary access URLs or license acceptance tokens in git/issues/logs.
2. Obtain **both** (a) DINOv3 ViT-L/16 **LVD-1689M** backbone and (b) the **ViT-L/16 dino.txt vision head + text encoder** adapter. Check that the files match the official Hub entrypoint (not DINOv2 weights or standalone DINOv3 backbone only).
3. Record the exact **upstream Git commit SHA** for `facebookresearch/dinov3`; record each checkpoint's official source name, content SHA-256, size, access mechanism and terms without publishing a gated or signed download URL.
4. Confirm `torch.hub.load(..., weights=..., backbone_weights=..., bpe_path_or_url=...)` runs independently with that pinned upstream revision. Capture output shapes, official tokenizer behavior, image preprocessing, patch features, `get_logits()` / patch/similarity-map APIs that are actually supported. Do not assume DINOv2+dino.txt patch or dense outputs have identical behavior.
5. Apply the license-version and distribution decisions above **before copying any upstream code**. Prefer an optional official dependency with user-provided/cache-local weights, attribution, no bundled Meta weights, and no unchecked remote-code execution on user inputs. If redistributing any Meta code, modified code, vocabulary, weights or derivatives, include the applicable complete Agreement and obtain a license review when uncertain.
6. Only then add a separate `dinov3-dinotxt` Registry backend and distinct `EmbeddingSpace`; compare image/text features and logits against a separately loaded official reference on deterministic CPU inputs. Explicitly label unsupported functions and unavailable precision combinations.
7. Add a light mock-based Factory/Registry/regression suite; keep real-weight integration opt-in, outside normal CI, and require measured parity before stable v0.8.0 support claims.

## Release gate

A documented license decision and successful official real-model parity are mandatory. If the model downloads are inaccessible or the license review is unresolved, leave DINOv3 out of the **published** v0.8.0 release rather than claiming support.
