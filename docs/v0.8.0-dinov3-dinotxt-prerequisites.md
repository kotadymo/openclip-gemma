# DINOv3 + dino.txt — prerequisites for v0.8.0

**Status:** Official API and a named checkpoint are identified. License acceptance, exact artifact provenance and real numerical validation are **not yet complete**. This note does not assert the backend is implemented.

## Confirmed from Meta's official repository

- Source: https://github.com/facebookresearch/dinov3
- Official zero-shot head Hub entrypoint: `dinov3_vitl16_dinotxt_tet1280d20h24l` in `dinov3/hub/dinotxt.py`
- Official method: `torch.hub.load(REPO_DIR, "dinov3_vitl16_dinotxt_tet1280d20h24l", weights=HEAD_CHECKPOINT, backbone_weights=BACKBONE_CHECKPOINT)`
- Default dino.txt adapter weight enum: `DINOTxtWeights.LVTD2300M`
- Default backbone: `dinov3_vitl16`, `BackboneWeights.LVD1689M` (ViT-L/16 distilled).
- Combined dino.txt output dimension: `2048`; vision backbone patch size `16`; text encoder width `1280`, `20` attention heads, `24` blocks; context length `77`. These values are present in the official Hub configuration.
- Required official BPE vocabulary: `https://dl.fbaipublicfiles.com/dinov3/thirdparty/bpe_simple_vocab_16e6.txt.gz` (check linked vocabulary license separately).
- Upstream code **and model weights** are under the [DINOv3 License](https://github.com/facebookresearch/dinov3/blob/main/LICENSE.md), **not Apache-2.0**. This license includes conditions for redistribution and research acknowledgments.

## Actions required before implementation / publication

1. **User action:** visit https://ai.meta.com/resources/models-and-libraries/dinov3-downloads/ and review/accept the DINOv3 license as applicable. Meta says accepted users receive an email listing download URLs for backbones and adapters. Do not store credentials, temporary access URLs or license acceptance tokens in git/issues/logs.
2. Obtain **both** (a) DINOv3 ViT-L/16 **LVD-1689M** backbone and (b) the **ViT-L/16 dino.txt vision head + text encoder** adapter. Check that the files match the official Hub entrypoint (not DINOv2 weights or standalone DINOv3 backbone only).
3. Record the exact **upstream Git commit SHA** for `facebookresearch/dinov3`; record each checkpoint's official source name, content SHA-256, size, access mechanism and terms without publishing a gated or signed download URL.
4. Confirm `torch.hub.load(..., weights=..., backbone_weights=..., bpe_path_or_url=...)` runs independently with that pinned upstream revision. Capture output shapes, official tokenizer behavior, image preprocessing, patch features, `get_logits()` / patch/similarity-map APIs that are actually supported. Do not assume DINOv2+dino.txt patch or dense outputs have identical behavior.
5. Decide licensing and distribution architecture **before copying any upstream code**. Preferred design is an external, optional official dependency with user-provided/cache-local weights, separate attribution/license documentation, no bundled Meta weights, and no unchecked remote-code execution on user inputs. Obtain a license review if redistributing derivative code.
6. Only then add a separate `dinov3-dinotxt` Registry backend and distinct `EmbeddingSpace`; compare image/text features and logits against a separately loaded official reference on deterministic CPU inputs. Explicitly label unsupported functions and unavailable precision combinations.
7. Add a light mock-based Factory/Registry/regression suite; keep real-weight integration opt-in, outside normal CI, and require measured parity before stable v0.8.0 support claims.

## Release gate

A documented license decision and successful official real-model parity are mandatory. If the model downloads are inaccessible or the license review is unresolved, leave DINOv3 out of the **published** v0.8.0 release rather than claiming support.
