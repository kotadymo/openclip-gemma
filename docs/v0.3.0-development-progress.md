## Completed

- Implemented and exported `list_models()`, `list_pretrained()`, and
  `create_model_from_pretrained()`. The `"official"` tag is an alias for the
  existing fixed model ID and revision.
- Added explicit `output_dict` and `logit_scale_mode` options to model
  factories. The default strict mode refuses to invent a trained CLIP
  `logit_scale`; explicit cosine mode returns uncalibrated cosine behavior.
- Implemented `forward()` and `get_logits()` without changing the existing
  image/text encoder implementation or the v0.2.0 index formats.
- Added Factory, Model, and public-export unit tests.
- Added a CPU/CUDA FP32/BF16 real-model compatibility integration test.
- Ran the pinned OpenCLIP source commit in a temporary environment, using a
  randomly initialized CPU `ViT-B-32` model for API/shape checks. OpenCLIP
  pretrained weights were not downloaded.
- Added the ten-case compatibility report and migration guide.
- Updated README, CHANGELOG, Copilot instructions, wheel import CI expectations,
  release verification defaults, and v0.3.0 TestPyPI/production workflows.
- Updated package metadata and lockfile to v0.3.0 without changing runtime
  dependencies.

## Finalization validation (2026-10-19)

- Added `examples/openclip_compatibility_v030.py`, a runnable Factory/Model
  example with a synthetic image by default and an optional `--image` path.
  It exercises tuple and dictionary `forward()` results and `get_logits()`.
- The example passed on CPU FP32, CPU BF16, RTX 4070 Ti SUPER CUDA FP32, and
  CUDA BF16. All tuple/dict feature differences and `get_logits()` versus
  direct cosine differences were `0.0`. Output shapes were `[1, 768]` and
  `[2, 768]`; output dtype/device matched the requested mode.
- A pinned Sentence Transformers reference comparison measured CPU FP32
  maximum absolute errors of `3.2223761081695557e-7` for images and
  `3.982335329055786e-6` for text. The same CPU BF16 comparisons measured
  `0.0` for both. An additional CUDA FP32 reference run measured
  `2.682209014892578e-7` for image embeddings and
  `5.345791578292847e-6` for text embeddings. See the compatibility report
  for score-matrix, CPU/CUDA parity, and allocator-memory measurements.
- Re-ran all opt-in integration tests after the CPU BF16 fallback:
  `21 passed, 0 failed, 0 skipped, 164 deselected` in 863.50 seconds.
- Re-ran the ordinary suite: `160 passed, 25 skipped` in 4.60 seconds. These
  default-run skips are the opt-in model integration tests and CUDA-only unit
  cases; the full integration selection above was run separately.
- Ruff passed; `uv lock --check` passed.
- Fresh v0.3.0 wheel and sdist built and passed `verify_wheel.py` and

- Added `docs/release-checklist-v0.3.0.md` with the ordered RC, TestPyPI,

- GitHub Actions push run `39175553528` and PR run `39175556147` both

## Evidence limitations

- OpenCLIP runtime checks used random weights and CPU only. They validate API
  call/return behavior and shapes, not numerical equivalence or pretrained
  retrieval quality.
- OpenCLIP's real pretrained factory checkpoint download was not executed.
- EmbeddingGemma was checked against its pinned Sentence Transformers
  implementation and across CPU/CUDA, but no claim of CLIP numerical
  equivalence is made.
- Repository CI has no CUDA hardware; the CUDA results above came from the
  development PC's RTX 4070 Ti SUPER.
