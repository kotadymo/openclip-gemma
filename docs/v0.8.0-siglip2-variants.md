These revisions come from the Hugging Face model commit history. Pinning prevents silent model/processor drift. All three checkpoints have `model_type=siglip` and are loaded through the fixed-resolution `AutoModel` and `AutoProcessor` path without remote code. SigLIP 2 Large and SO400M use their own projection dimensions; the old constant 768 must not be applied to them. The `siglip2-base` (224) and `siglip2-naflex-base` entries remain unchanged.

## Validation and remaining checks

1. CPU FP32 comparisons passed against separate pinned `AutoModel`/`AutoProcessor` instances. Processor tensors and tokenizer IDs matched exactly; raw and normalized image/text embeddings and sigmoid logits had maximum absolute error `0.0` for the deterministic test inputs.
2. Image-index build and search passed for each checkpoint. SO400M loaded and ran on the recorded CPU host; CUDA FP32/BF16 and GPU memory use remain unverified.
3. Transformers emitted the pinned config warning that BOS/EOS token IDs `49406`/`49407` are outside the text vocabulary size `32000`. The wrapper and independent reference produced identical tensors and outputs; no checkpoint configuration was changed.
4. The pinned HF cards identify Apache-2.0. Model weights are downloaded at runtime and are not included in the package.
5. SO400M's model.safetensors is approximately 4.54 GB; do not make all-checkpoint heavyweight parity a normal CI gate.

Model sources: https://huggingface.co/google/siglip2-base-patch16-384 ; https://huggingface.co/google/siglip2-large-patch16-256 ; https://huggingface.co/google/siglip2-so400m-patch14-384 .
