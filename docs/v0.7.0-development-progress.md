## Phase 0 findings

- The four HF repositories and immutable revisions, source hashes, model-file hashes, and license findings are recorded in [model provenance](./model-provenance-v0.7.0.md). The downloaded SigLIP and Qwen 2B weight files were locally SHA-256 checked against the pinned HF LFS digests. Qwen 8B weights were not downloaded.
- SigLIP 2 FixRes and NaFlex both loaded on CUDA in FP32 and BF16. FP32 outputs were 768-dimensional and the learned scale/bias logits matched the official formula within `9.54e-7` (FixRes) and `0.0` (NaFlex). Measured BF16-vs-FP32 feature and logit deltas are recorded in the provenance document; these were single synthetic-input precision probes, not benchmarks.
- The pinned Qwen 2B wrapper loaded in CUDA FP32 and BF16. Text-only, image-only, and mixed text-image inputs returned finite `(3, 2048)` outputs; BF16-vs-FP32 maximum absolute difference was `0.00418`. Two-frame video-only and text-video inputs returned finite `(2, 2048)` BF16 outputs.
- The Qwen 2B card advertises user-defined dimensions 64-2048. Sentence Transformers 5.4.0 produced dimensions 64, 257, 1024, and 2048, and its `normalize_embeddings=True` option normalizes after truncation. However, its default text path prepends the instruction to plain text (11 tokens), whereas pinned `Qwen3VLEmbedder.process` uses the chat template with system/user/assistant-generation messages (25 tokens). Same-text BF16 embeddings differed by up to `0.05670`. Do not assume these routes or their indexes are compatible.
- The v0.7.0 specification explicitly selects pinned `Qwen3VLEmbedder.process` as the reference. Recommended resolution is to keep that path canonical and document the Sentence Transformers route as a separate embedding strategy, but do not implement or claim Qwen MRL parity until the intended input and truncation/normalization contract is confirmed.
- The pinned Qwen source uses `trust_remote_code=True` and converts vision-processing exceptions to a `"NULL"` input. Tests used the audited source file and fixed local checkpoint; OpenVLCLIP must not adopt unpinned remote code or silently produce NULL embeddings.
- The project lock resolves Torch 2.14.1, Torchvision 0.29.1, and Transformers 5.20.1. Qwen 2B and both SigLIP checkpoints ran in an isolated Windows Python 3.12 environment with Torch `2.14.1+cu130`, Transformers `5.20.1`, and `qwen-vl-utils==0.0.14`. This is a single-host CUDA check, not Windows/Linux/Python-matrix or CPU validation. No project dependency or lockfile was changed.

## Blocking GPU requirement

The system Python 3.12.10 still has CPU-only Torch `2.14.0+cpu`. An isolated temporary environment has CUDA 13.0, Torch `2.14.1+cu130`, Transformers `5.20.1`, and BF16 support on an NVIDIA RTX 4070 Ti SUPER with 16,376 MiB total and 14,363 MiB free at the latest check.

The pinned Qwen 8B checkpoint contains 8,144,793,840 BF16 parameters in four shards totaling 16,289,679,624 bytes (15.17 GiB). Its weights alone exceed currently free VRAM, leaving no room for inference activations or buffers. Only its small pinned metadata was fetched; its weight shards were not downloaded or executed. The repository has no configured self-hosted Actions runners. Therefore the mandatory Qwen 8B GPU parity gate cannot be completed here.

**Required to resume Phase 0:** provide access to a CUDA-enabled high-memory GPU host with enough free VRAM for the full BF16 checkpoint and runtime buffers. A 24 GiB-or-larger device is a practical starting point, not a measured minimum. Verify the environment with:

```powershell
nvidia-smi --query-gpu=name,memory.total,memory.free --format=csv
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.version.cuda)"
```

Do not substitute quantization or unverified CPU offload. Once a suitable GPU is available, run the official Qwen 8B reference with the fixed revision and record peak VRAM. Resolve the Qwen reference-path discrepancy and finalize the MRL truncation/normalization contract before Phase 1 begins.
