## Phase 0 findings

- The four HF repositories and their immutable revisions are recorded in `docs/model-provenance-v0.7.0.md`.
- Both SigLIP checkpoints declare Apache-2.0 and resolve to different Transformers model classes. NaFlex requires processor-aware `pixel_values`, valid-patch masks, and spatial shapes.
- Both Qwen checkpoints declare Apache-2.0 and use BF16 weights. The pinned official embedding source uses chat-template construction, Qwen's multimodal processor, last-valid-token pooling, and optional post-pooling L2 normalization.
- The Qwen official wrapper sets `trust_remote_code=True` and turns vision-processing failures into a `"NULL"` input. Neither behavior may be adopted uncritically in OpenVLCLIP.
- The Qwen model cards claim MRL output ranges, but the pinned `Qwen3VLEmbedder.process` source has no truncation argument or implementation. Exact truncate and normalization behavior remains to be verified against an independent official/reference path.
- The project lock resolves Torch 2.14.1, Torchvision 0.29.1, and Transformers 5.20.1; the official Qwen repository manifest requests Torch 2.8.*. No compatibility test has been run, and no dependency downgrade has been made.

## Blocking GPU requirement

The local Python 3.12.10 interpreter has Torch `2.14.0+cpu`; CUDA is unavailable to PyTorch, and Transformers/Torchvision are not installed. `nvidia-smi` shows a 16,376 MiB device with 14,735 MiB currently free.

The pinned Qwen 8B checkpoint contains 8,144,793,840 BF16 parameters in four shards totaling 16,289,679,624 bytes (15.17 GiB). The weights alone exceed currently free VRAM, leaving no space for inference activations or buffers. The repository has no configured self-hosted Actions runners. Therefore the mandatory Qwen 8B GPU parity gate cannot be completed here.

**Required to resume:** provide access to a CUDA-enabled high-memory GPU host with enough free VRAM for the full BF16 checkpoint and runtime buffers. A 24 GiB-or-larger device is a practical starting point, not a measured minimum. Verify the environment with:

```powershell
nvidia-smi --query-gpu=name,memory.total,memory.free --format=csv
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.version.cuda)"
```

Do not substitute quantization or unverified CPU offload. Once a suitable GPU is available, first run the official Qwen 8B reference with the fixed revision and record its peak VRAM; then complete the outstanding Qwen MRL reference check. Only after those Phase 0 gates pass may Phase 1 begin.
