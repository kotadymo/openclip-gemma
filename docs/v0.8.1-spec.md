# OpenVLCLIP v0.8.1 — Small patch release specification

**Decision date:** 2026-10-24  
**Status:** PLAN ONLY; implementation, version bump, tag and publication are **not** authorized by this document.  
**Baseline:** [v0.8.0](https://github.com/kotadymo/openvlclip/releases/tag/v0.8.0), commit `907060b710cb1f2301335f4a86ddd44acdadf67e` (PR #58 included). Check the current `main` and open PRs before coding.  
**Goal:** A narrow, backwards-compatible patch to correct release-facing documentation, close the new SigLIP 2 post-padding-fix validation gap, and reject malformed PE-Core text lengths early.

## 1. In scope and priority

| Priority | Change | Primary files | Acceptance |
| --- | --- | --- | --- |
| P0 | Correct v0.8.0's published status and document v0.8.1 clearly | `README.md`, `CHANGELOG.md`; brief addenda to v0.8.0 status docs only if essential | No obsolete v0.7.1-as-latest or v0.8.0-unreleased wording anywhere in README; historical notes remain identifiable, and the existing README validator passes without relaxing it |
| P0 | Re-run **post-PR #58** official, unmasked-path CPU FP32 numerical parity on the **three v0.8.0-added SigLIP 2 checkpoints only** | Existing `tests/integration/test_siglip2_official_parity.py`; record outcome in `docs/v0.8.1-validation.md` | Record a real PASS/FAIL/BLOCKED outcome for each model; **all three must PASS for release readiness**, but a blocked run does not prevent a documentation/code PR |
| P1 | Reject non-32-token PE-Core input before calling OpenCLIP | `src/openvlclip/backends/pe_core.py`, `tests/test_pe_core_backend.py` | `LongTensor[B,32]` with B>0 works; lengths 0, 1, 31 and 33 reject with actionable `ValueError`, without a checkpoint download |
| Release preparation, **later** | Update version and release artifacts only after the parity release gate passes | `pyproject.toml`, `uv.lock`, `CHANGELOG.md`, README | **All three** post-fix parity checks PASS before a v0.8.1 version bump/release-ready claim; wheel/sdist and existing required CI pass; publication remains separately authorized |

This is **not** a new model release. Keep **all 10 existing checkpoints** unchanged, along with their model IDs, pinned revisions, preprocessing, text-padding behavior fixed by PR #58, embedding dimensions, prompt policy and score semantics. Do not modify embedding-space identities, index archive formats, image/video retrieval ranking, public signatures, optional dependency names, or model weights.

Explicitly **out of scope:** DINOv3, DINOv3+dino.txt, FAISS/ANN, new model families, retraining, new CLI/UI, search re-optimization, rebenchmarking the 54-case search matrix, all-model / GPU test sweeps, and unrelated refactors or CI expansion.

## 2. Requirements in detail

### R1 — Release-facing documentation (P0)

- The actual v0.8.0 release exists on [GitHub](https://github.com/kotadymo/openvlclip/releases/tag/v0.8.0) and [PyPI](https://pypi.org/project/openvlclip/0.8.0/). On the baseline commit, `README.md` still calls v0.7.1 the published release and describes the ten-checkpoint Registry as source-only. `CHANGELOG.md` still labels v0.8.0 `Unreleased`. Correct these statements.
- In `CHANGELOG.md`, label v0.8.0 as **released** (2026-10-23 UTC / 2026-10-24 JST) and record the already-merged **SigLIP 2 official no-attention-mask text-padding correction** from PR #58 as a v0.8.0 fix. Keep existing v0.8.0 features and known limitations accurate. Add a brief v0.8.1 patch entry; mark it *unreleased* during implementation and mark it released only when an actual release is confirmed.
- Make the README's supported-model summary version-neutral where possible, with ten checkpoints in the released v0.8.0 line, `[pecore]` installation instructions, and an explicit statement that Qwen3-VL-Embedding-8B is not supported. Historical v0.7.1 installation/release notes may stay but must be clearly labeled historical; never blindly replace all `0.7.1` occurrences.
- Avoid claiming v0.8.1 is already on PyPI before publication. The built distribution's README must not contradict its declared version or available models. Inspect **the entire README**, especially the overview, Features, Installation, OpenCLIP-compatibility overview and the lower **v0.8.0 source registry and installation** section; do not stop after the first paragraph. 
- Keep release statements *historical and factual* (e.g. “OpenVLCLIP v0.8.0 was published on PyPI and GitHub Releases in October 2026; it contains ten registered checkpoints.”), not a fragile “the latest/current release is v0.8.0” claim. The existing `tools/readme_validation.py` / `tests/test_readme_validation.py` intentionally reject time-sensitive “latest/current release” wording. Run those existing checks; correct the README instead of weakening the validator or adding new release-specific checks.

### R2 — Post-padding-correction SigLIP 2 parity (P0)

PR #58 changed `Siglip2Backend.encode_text()` to call the official Transformers path **without passing a synthesized PAD attention mask**. Historical v0.8.0 validation (see `docs/v0.8.0-validation.md`, sections `Pinned-checkpoint CPU FP32 parity` and `SigLIP 2 text-padding correction`) explicitly distinguishes the former masked-path results from the corrected unmasked path. The corrected follow-up diagnostic covered the two original Base variants, **not** the three new FixRes checkpoints.

Run the **existing** opt-in reference test only for:

| Model name | Pinned Hugging Face revision | Dimension / image size |
| --- | --- | --- |
| `siglip2-base-384` | `f775b65a79762255128c981547af89addcfe0f88` | 768 / 384px |
| `siglip2-large-256` | `787800c8990e6f058423089178e718139608408c` | 1024 / 256px |
| `siglip2-so400m-384` | `e8e487298228002f3d8a82e0cd5c8ea9c567f57f` | 1152 / 384px |

- Compare independently instantiated `transformers.AutoModel`/`AutoProcessor` references with the OpenVLCLIP wrapper **on the same official, unmasked input path**. Confirm preprocessed pixels, tokenizer IDs, raw and normalized image/text features, and bidirectional scaled/bias logits using the *existing test's* FP32 `rtol=atol=1e-5` acceptance criterion. The existing test also builds and queries a tiny two-image index.
- **Do not** silently revert PR #58, synthesize `attention_mask` for the official reference, change model IDs/revisions, or accept parity produced by mocks. Do not change the tolerance or reference path merely to obtain a pass.
- Record three individual PASS/FAIL/BLOCKED results in a new concise `docs/v0.8.1-validation.md`, with exact SHA, pinned checkpoint, reference/torch/transformers versions, OS/device/dtype, input, metric/tolerance, executed command and failure/resource caveats. Never report numerical error as `0.0` unless measured.
- Run the weights-heavy tests **manually/opt-in**, **one checkpoint per fresh pytest process** (three separate invocations, not one process running three checkpoints) to limit RAM use and allow selective reruns. No new normal CI job, model-loading matrix or benchmark harness. If checkpoints/hardware/network are unavailable, record the affected result as BLOCKED rather than inventing PASS; do not broaden into CUDA testing to bypass CPU conditions. Continue with the other checkpoints when feasible.
- These SigLIP 2 reference tests depend on the normal project dependencies and pytest; they **do not directly require the optional `integration` extra** (`sentence-transformers[image]`). Prefer an already prepared development environment and **omit `--extra integration`** to avoid unnecessary installation. Do not run a broad dependency sync or download optional extras just for this check.
- Suggested PowerShell invocation from the repository root (each `uv run` starts a separate pytest process):

```powershell
$env:OPENCLIP_GEMMA_RUN_INTEGRATION = "1"
$models = @("siglip2-base-384", "siglip2-large-256", "siglip2-so400m-384")
foreach ($model in $models) {
    uv run --locked pytest -q -s `
      tests/integration/test_siglip2_official_parity.py `
      -k "cpu and fp32 and $model"
    if ($LASTEXITCODE -ne 0) {
        Write-Warning "Validation FAILED or BLOCKED for $model; preserve output and investigate only this case."
    }
}
```

  First confirm pytest selection is **exactly one CPU FP32 case** per invocation and that it ran rather than skipped; the total successful result is **three real PASS cases**. Capture each process's exit code and output in `docs/v0.8.1-validation.md`, distinguishing an assertion mismatch (FAIL) from missing weights, network or RAM (BLOCKED). If dependencies are missing, install only necessary packages and record the deviation. Avoid unrelated GPU or pre-existing checkpoint tests.

### R3 — PE-Core strict text shape (P1)

In `src/openvlclip/backends/pe_core.py`, `PECoreBackend.encode_text()` currently accepts `LongTensor[B,L]` for `1 <= L <= 32`. The pinned PE-Core OpenCLIP text transformer has a **fixed 32-position embedding**, so a smaller unpadded input is likely to cause a lower-level shape error; longer input is already rejected.

- Require `text.dtype == torch.long`, `text.ndim == 2`, **`B >= 1`**, and **`L == PE_CORE_CONTEXT_LENGTH` (32)**. On a valid tensor with an invalid sequence length, raise `ValueError` containing `32` and guidance to use `get_tokenizer(model_name)` to obtain a padded native input. Keep the existing `TypeError` behavior for non-tensor/wrong dtype/rank if feasible.
- Do **not** silently pad or truncate externally supplied text IDs. That would change tokens, EOS placement, or inference semantics.
- Add focused parametrized unit checks in `tests/test_pe_core_backend.py` for both T/S backends, lengths 0/1/31/33, empty batch, and valid B=1 and B=2 with 32 tokens; mock only the OpenCLIP load, not this validation. Ensure `model.encode_text` and `model.get_logits` reject invalid lengths consistently.
- Existing `get_tokenizer()` already emits native 32-token output; do not change it. Update any misleading docstring/error wording.

## 3. Minimal verification and acceptance

**Required low-cost checks (adapt names to current tree):**

```bash
uv run --locked pytest -q tests/test_pe_core_backend.py tests/test_siglip2_backend.py tests/test_siglip2_variants_v080.py tests/test_registry.py tests/test_readme_validation.py
uv run --locked ruff check src/openvlclip/backends/pe_core.py tests/test_pe_core_backend.py
uv lock --check
```

- Keep normal CI as-is; no new OS/Python test matrix, no routine downloading official weights, no full regression reruns unless a focused check uncovers a concrete cross-module defect.
- **Do not couple documentation/PE-Core implementation to availability of large model weights:** R1 and R3 may be implemented, tested, committed, and submitted in one small PR even if one or more R2 runs are BLOCKED or FAIL. Include `docs/v0.8.1-validation.md` showing exact results and outstanding blockers. Such a PR is **not release-ready**; do not quietly omit validation or misstate its outcome.
- **Release gate, separately from PR creation:** after all three opt-in checkpoint parity tests **PASS**, update `pyproject.toml` to `0.8.1` and synchronize `uv.lock`; build and inspect one wheel + sdist with the existing tools (`uv build`, `tools/verify_wheel.py`, `tools/verify_sdist.py`) and run the existing required CI. If any parity case is BLOCKED or FAIL, leave the version at the current released value for now and report the unresolved model; there is no release-ready claim, release tag, or PyPI publication.
- Acceptance for a **code/documentation PR**: R1 text corrected and existing README validation passes; R3 both PE-Core variants enforce exactly 32 tokens; all three R2 outcomes accurately documented, including any BLOCKED/FAIL status; ten-model Registry and core API/index compatibility maintained; focused checks pass. Acceptance for **v0.8.1 release readiness** additionally requires R2 three real-weight official-path PASS results, a synchronized v0.8.1 version/lock, successful wheel/sdist checks, and passing existing required CI. No new externally gated dependencies or licenses.
- If tests reveal additional issues, fix only direct blockers to these requirements; document unrelated findings for a later release.

## 4. Implementation handoff and publication boundary

1. Inspect current `main`, recent PRs and file differences; avoid duplicate changes.
2. Fix PE-Core's input validation and the minimal unit tests. Update README and CHANGELOG, preserving historical notes.
3. Run the three selected corrected-path SigLIP 2 parity cases and record the **actual** evidence in `docs/v0.8.1-validation.md`.
4. Open one small implementation PR for R1/R3 and the honest R2 validation record **regardless of model-resource availability**; do not block that PR on weight downloads. If all three R2 tests PASS, the same PR may also bump the version and lock, verify distributions, and run existing required CI. If a test is BLOCKED/FAIL, omit the version bump and label the PR **not release-ready**, with remaining actions documented. Merge only if required checks pass and the user has asked for a merge; otherwise report the PR status.
5. Provide a concise **Japanese** report with changed files, commit/PR URLs, exact executed tests/results, three parity outcomes, and any blockers.

**Do not create/push `v0.8.1` tag, publish PyPI, create a GitHub Release or change Trusted Publishing controls as part of patch implementation.** Production publication requires a **separate explicit instruction** after code review. Note that the shared `.github/workflows/publish-pypi.yml` automatically publishes on a pushed `v*` tag, and the protected `pypi` Environment may need a **v0.8.1 tag allowlist entry and required-reviewer approval** during that future, separately authorized release action.
