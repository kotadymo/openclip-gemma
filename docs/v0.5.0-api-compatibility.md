# OpenVLCLIP v0.5.0 API Compatibility Baseline

This Phase A document records the inference contract inherited from
`openclip-gemma==0.4.0`. Phase A adds compatibility tests and baseline data
only; it does not change the distribution name, import name, model behavior,
or release configuration.

## Supported inference surface

The root package exports `EmbeddingGemmaCLIP`, `create_model()`,
`create_model_and_transforms()`, `create_model_from_pretrained()`,
`get_tokenizer()`, `list_models()`, and `list_pretrained()`. The only real
model is `embeddinggemma-2`, backed by the fixed
`google/embeddinggemma-2` revision declared in the baseline manifest.
Model-name matching trims whitespace, ignores case, and treats underscores
as hyphens. The `official` pretrained tag is an alias for the pinned model;
`pretrained=None`, unknown model names, checkpoints, options, devices, and
unsupported precisions fail explicitly.

`create_model_and_transforms()` returns three values, with deterministic
train and validation transforms. `create_model_from_pretrained()` returns
`(model, preprocess_val)` by default and only the model when
`return_transform=False`. Tokenization uses the official EmbeddingGemma
tokenizer and its configured task prompts. Callers must not reuse CLIP token
IDs or substitute CLIP image preprocessing.

Image and text encoders preserve batch order and return tensors with a
768-dimensional default. Supported MRL dimensions are 768, 512, 256, and
128; reduced outputs retain leading dimensions and are L2-normalized after
truncation. EmbeddingGemma's official pooling path already returns normalized
768-dimensional embeddings when `normalize=False`; this option does not
request raw hidden states. The existing `normalize=True` behavior remains.

`forward()` and `get_logits()` are strict by default because EmbeddingGemma
does not have a trained OpenCLIP logit scale. They are available only when
`logit_scale_mode="cosine"` is explicit. The returned scale is the untrained
multiplier 1.0, and the scores are cosine similarities, not trained CLIP
logits or probabilities.

FP32 remains the numerical baseline. BF16 remains supported under the
existing CPU/CUDA validation conditions; FP16 and `.half()` remain
unsupported. Selective loading requires text and optionally retains the image
tower. The existing factory also accepts sequence inputs such as a list for
`modalities` and canonicalizes the result to text-before-image order.
Precision spellings `fp32`/`float32` and `bf16`/`bfloat16` remain accepted
case-insensitively.

## Intentional differences from OpenCLIP

| Area | OpenVLCLIP v0.5.0 contract |
| --- | --- |
| Model discovery | Only `embeddinggemma-2` is registered; arbitrary OpenCLIP architectures and checkpoints are not loaded. |
| Tokenization | Gemma token IDs and EmbeddingGemma task prompts are model-specific and are not interchangeable with CLIP tokens. |
| Image preprocessing | Use the returned deterministic EmbeddingGemma transform; CLIP resizing, cropping, and normalization are not equivalent. |
| Default embedding | 768-dimensional, official-pooling output; `normalize=False` does not expose raw features. |
| Similarity | Strict by default; explicitly opt into cosine mode. No trained CLIP `logit_scale`, probabilities, training API, or FP16 support is claimed. |
| Training transform | The train transform is deterministic and equal to validation preprocessing; it does not provide training augmentation. |

The detailed A/B/C scenario comparison and its evidence are in the
[v0.3.0 compatibility report](./openclip-compatibility-report-v0.3.0.md).
The confirmed Factory and Model rules are in the
[v0.3.0 compatibility specification](./openclip-compatibility-v0.3.0.md).

## Numerical regression control

The immutable CPU FP32 vectors in
[`tests/fixtures/v0.4.0_api_baseline.npz`](../tests/fixtures/v0.4.0_api_baseline.npz)
were captured from the v0.4.0 implementation at release commit
`2dea1f1ba4572e5ae9e469d8f4bd071246565dd4`. The source and existing tests in
the Phase A starting tree were checked to have no changes from that release
tag. Input image geometry, text batch, `SearchQuery` prompt, model revision,
and comparison thresholds are recorded in the adjacent JSON manifest.

The opt-in
[`v0.4.0 baseline integration test`](../tests/integration/test_v040_api_baseline.py)
compares image and text embeddings against the saved vectors and verifies all
four MRL dimensions, including L2 normalization after truncation. It uses a
maximum absolute error of `1e-4` and minimum cosine similarity of `0.9999`.
The baseline fixture contains embeddings only, not model weights.

The baseline test can be run with:

```powershell
$env:OPENCLIP_GEMMA_RUN_INTEGRATION = "1"
python -m pytest tests/integration/test_v040_api_baseline.py -q -s
```

BF16, CUDA, selective-loading, tokenizer-reference, and preprocessing
regressions remain covered by the existing opt-in integration tests. Hardware
that is unavailable must be reported as unverified rather than passed.
