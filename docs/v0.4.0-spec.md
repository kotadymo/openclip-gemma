# openclip-gemma v0.4.0 Specification

## Status and compatibility baseline

This specification defines the v0.4.0 release scope. It extends the v0.3.0
model contract without changing the default 768-dimensional inference result,
task prompts, preprocessing, precision behavior, or strict-by-default
`forward()`/`get_logits()` policy. The model remains pinned to
`google/embeddinggemma-2` revision
`914f7f89142e33e77833254d9c9b90c3cef7303b`.

The official EmbeddingGemma 2 model card confirms leading-dimension MRL
truncation at 768, 512, 256, and 128 dimensions and requires L2
re-normalization after truncation. Its published benchmark table is model-card
evidence, not a benchmark result for this package or a guarantee for a
particular application. No v0.3.0 compatibility specification is changed.

## Public model API

`EmbeddingGemmaCLIP.encode_image()` and `encode_text()` add the keyword-only
argument `truncate_dim: int | None = None`. `None` means the existing 768
dimensions. The only valid explicit values are 768, 512, 256, and 128; booleans
and non-integers are rejected as type errors, and other integer values are
rejected as value errors.

For a dimension below 768, the implementation keeps the first `truncate_dim`
features and L2-normalizes that slice. This is applied after the existing
official pooling and normalization path for both modalities. The existing
`normalize` argument keeps its v0.3.0 meaning. In particular, omitting
`truncate_dim` does not add an operation to the 768-dimensional path.

`forward()` and `get_logits()` add the same keyword-only `truncate_dim`
argument so both modalities always use one dimension in a call. Their
existing `logit_scale_mode="strict"` default, errors, return shapes, and
cosine-only semantics remain unchanged. At a reduced dimension,
`get_logits()` returns cosine similarities between the re-normalized
truncated features; they are not trained CLIP logits or probabilities.

## Image and video indexing

`build_or_update_image_index()` and `build_or_update_video_index()` add
`embedding_dim: int = 768`. They accept the same four dimensions as the model
API. Streaming image embedding accepts `truncate_dim`; video-frame batching
uses the selected dimension as well. The existing default remains 768.

Search APIs do not take a dimension argument. They read and validate the
saved index dimension, request a query embedding of that dimension, validate
its exact shape, and only then score it against the stored vectors. An update
with a different dimension is rejected instead of mixing vectors or silently
re-embedding a collection. The index can be explicitly converted or rebuilt.

New image indexes use format version 2; new video indexes use format version
3. New metadata records the supported `embedding_dimension`, the
`embedding_strategy` (`leading-dimensions-l2-v1`), model ID and pinned
revision, model precision, preprocessing/sampling identifiers, float32
storage format, record counts, and the existing embedding checksum. Loaders
validate these fields, metadata types, and the array shape together.

Backward compatibility:

- Image format version 1 remains readable only as a 768-dimensional index.
- Video format version 2 remains readable only as a 768-dimensional index.
  The older absolute-PTS video format version 1 remains unsupported, as in
  v0.3.0.
- Existing archive size checks, NPY-header preflight, pickle-disabled loading,
  checksum validation, and atomic replacement remain in force.
- Unknown versions, unsupported dimensions, inconsistent metadata, corrupt
  arrays, and incompatible model/revision/precision are explicit errors.

## Index conversion

The image-search and video-search modules expose
`convert_image_index(source_index_dir, output_index_dir, *, embedding_dim)`
and `convert_video_index(...)`. Conversion reads and verifies an existing
archive, truncates every vector from its leading dimensions, re-normalizes it,
and writes a new-format archive atomically. It does not load model weights,
decode source media, or overwrite the source index. The destination must be a
different directory and must not already contain the corresponding index
archive.

Conversion to a larger dimension is rejected: discarded vector coordinates
cannot be reconstructed from a lower-dimensional index. Conversion to the
same or a smaller supported dimension is allowed. Rebuilding from original
media is the alternative when a higher-dimensional index is needed.

## Selective encoder loading

Factories add `modalities: tuple[str, ...] | None = None`.

- `None` preserves the existing full checkpoint-loading configuration.
- `("text",)` uses the pinned Transformers configuration mechanism to set
  `vision_config=None` and `audio_config=None`.
- `("text", "image")` preserves the image tower and sets `audio_config=None`.
- Text is required because it is the shared embedding backbone. Audio and
  video are not exposed as v0.4.0 inference APIs; other modality names,
  duplicates, and image-only requests fail explicitly.

The package uses the official Transformers `AutoConfig` fields and
`AutoModel.from_pretrained(..., config=...)` path. It does not remove or edit
model layers after construction. The pinned Transformers 5.20.1
configuration declares vision/audio sub-configurations optional, and its
`EmbeddingGemma2Model` constructs each corresponding tower only when that
configuration is present. The default path remains unchanged. Tests must
prove the omitted tower is absent, retained-modalities embeddings match the
default model within the established precision-specific tolerance, and
unavailable API calls fail clearly. Real memory measurements are recorded
only when measured.

## MRL benchmark

`benchmarks/benchmark_mrl.py` compares 128, 256, 512, and 768 dimensions on a
caller-supplied image collection. It records image embedding time, query
search latency, serialized index size and vector bytes, process RSS, and
CUDA allocator peak when CUDA is available.

An optional JSON query manifest contains `query` text and, when ground-truth
labels are available, `relevant_images` paths relative to the image root.
Outputs can be written as CSV or JSON. The benchmark reports:

- agreement with 768-dimensional rankings as a ranking-stability measure;
- Recall@K only when relevant-image labels are provided.

These measures are not interchangeable. Synthetic images or unlabelled
queries may exercise the benchmark code but are not evidence of real-world
retrieval quality. The report identifies the dataset, labels, model revision,
device, dtype, and run conditions, and marks unmeasured results explicitly.

## Error and failure behavior

- Invalid dimensions, modalities, source/destination paths, metadata, and
  query/index shape mismatches raise explicit errors.
- A failed conversion leaves the source index untouched and does not install a
  partially written destination archive.
- A failed index update leaves the last complete archive intact.
- No unsupported precision, model checkpoint, or modality is silently
  substituted.
- Expansion from a lower to a higher stored dimension is never represented as
  recovered data.

## Validation and release gates

Required lightweight tests cover all dimensions and invalid values, unchanged
768 output, normalization after truncation, forward/logits consistency,
streaming order, image/video index save/load/update/delete/search, legacy
768-format loading, conversion safety, malformed metadata, and CLI help.

Opt-in integration tests compare image and text MRL vectors with the pinned
Sentence Transformers reference after truncation and re-normalization. CPU
FP32/BF16 and CUDA FP32/BF16 are reported separately; unavailable hardware is
reported as unverified, never as passed. The benchmark must keep synthetic
execution checks separate from real, labelled retrieval evaluation.

Release preparation requires `uv lock --check`, the complete pytest suite,
Ruff, wheel/sdist builds and content verification, clean-wheel installation,
Windows/Linux CI for Python 3.12-3.14 (excluding Python 3.14.1), and available
model/platform checks. TestPyPI publication, clean installation, and
candidate validation precede final PyPI publication. Tags and publication
must target a CI-passing commit reachable from `main`, use Trusted
Publishing, and preserve GitHub Environment approvals. Existing release
tags and versions are never overwritten.

## Non-goals

v0.4.0 does not add training, fine-tuning, audio APIs, native video-clip
embeddings, arbitrary OpenCLIP architectures, FAISS/HNSW, or a learned CLIP
`logit_scale`. It does not claim retrieval-quality improvements without
labelled real-media measurements.
