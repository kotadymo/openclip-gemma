# v0.8.0 exact image/video search optimization

**Development scope:** Improve candidate selection in the existing NumPy exact-search engine. No FAISS dependency, ANN index, or persistent format change is introduced by this PR.

Previously, image/frame searches created Python score-row tuples for *all* 4096 scores in each block, then merged and sorted the whole candidate set. Native-video search sorted all scores in Python. The shared `select_top_k` helper now uses NumPy `partition` to identify the block-level top-k cutoff, materializing only candidates meeting that score cutoff, then applies the original secondary ordering.

**Tie semantics:** All rows tied at the cutoff are retained before applying the original secondary/path ordering, so the exact score, index, and tie priority are maintained. High-tie workloads may still process many candidates; this is intentional for correctness.

**Compatibility:** Index archives, model EmbeddingSpace settings, scores and public function signatures remain unchanged. The NumPy path remains the default and needs no extra dependency.

**Measurement caveat:** This reduces Python object creation and sorting work for low top-k and large indexes but is **not** evidence that all searches become faster; benchmark wall-clock latency and memory on representative 1k, 10k and 100k indices before publishing an end-to-end performance claim. Consider optional FAISS Flat/ANN as a separate measured change only if clearly beneficial and packaged safely on all supported systems.
