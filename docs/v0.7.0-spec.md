- **Repository:** https://github.com/kotadymo/openvlclip

## 1. 目的

v0.7.0では、既存のEmbeddingGemma 2とDINOv2 + dino.txtを維持しつつ、以下の**4チェックポイントすべて**を公式重みで実動作させる。

1. **SigLIP 2 FixRes Base**：`google/siglip2-base-patch16-224⟧
2. **SigLIP 2 NaFlex Base**：`google/siglip2-base-patch16-naflex⟧
3. **Qwen3-VL-Embedding-2B**：`Qwen/Qwen3-VL-Embedding-2B⟧
4. **Qwen3-VL-Embedding-8B**：`Qwen/Qwen3-VL-Embedding-8B⟧

同時にv0.6.1レビューで挙がった安定性・利便性の問題を対処し、PyPI公開を将来のバージョンでも再利用できる`.github/workflows/publish-pypi.yml⟧へ統一する。

**成功条件:** 4チェックポイントについて登録・ロード・画像／テキストEmbedding・画像検索・スコア計算の公式数値一致が成立する。Qwenの2B/8Bについては追加でネイティブ動画Embeddingと混合モーダルEmbeddingを検証する。全既存モデルの回帰、旧インデックス安全性、配布wheelの動作、公開ワークフローの安全性も確認する。

### 1.1 非目標

- Qwen3-VL-Reranker 2B/8B、別サイズのSigLIP 2、OpenAI CLIP等の追加。
- モデル学習、微調整、量子化された重みの正式サポート、全形式の動画デコーダの自作。
- `torch.compile⟧、FlashAttention 2必須化、`device_map="auto"⟧によるCPU/GPU自動オフロードの完全保証。
- SigLIP 2のdense特徴量をdino.txtのテキスト類似度マップと同等とみなすこと。
- Qwenの生成API・学習APIの提供。
- 新モデル同士、または既存モデルとのEmbedding空間共有を仮定すること。
- 全Windows/Python組み合わせで8BモデルをCPU実推論すること（依存関係・基本API検証と高メモリGPUでの実モデル検証を分離する）。

## 2. 基準バージョンと互換性原則

既存の公開エントリーポイント`create_model()⟧、`create_model_and_transforms()⟧、`create_model_from_pretrained()⟧、`get_tokenizer()⟧、`list_models()⟧、`list_pretrained()⟧を維持する。`create_model_and_transforms()⟧は常に3要素`(model, preprocess_train, preprocess_val)⟧を返す。

- EmbeddingGemma 2の既存既定モデル、768/512/256/128 MRL、task prompt、selective loading、検索API、固定v0.4.0基準Embeddingを保持する。
- dino.txtの2048次元global・1024次元patch・`similarity_map()⟧・公式logit-scale計算・Tokenizer・公式重みハッシュを保持する。dino.txtはMRL非対応。
- v0.6.1の`verify_contents=True⟧、動画PTSの正確なサンプリング、Native次元推論、古い画像・動画インデックスの読み込み／変換は維持する。
- 既存の`EmbeddingSpace⟧・Registry・Capabilitiesは互換性のある形で拡張する。古い保存形式や公開済みタグ・PyPI配布物を変更しない。
- 公開APIで未対応の機能を黙って別の方式へフォールバックさせない。`NotImplementedError⟧または引数エラーを明示する。
- 本仕様で将来追加するAPIは、既存の古いモデルでも未対応時の動作をテストする。

## 4. Registry / Backend構成

Registryの正式表示名を次とする（別名は衝突しない範囲だけ許可）。

```text
embeddinggemma-2
dinov2-dinotxt
siglip2-base
siglip2-naflex-base
qwen3-vl-embedding-2b
qwen3-vl-embedding-8b
```

新設候補：
- `src/openvlclip/backends/siglip2.py⟧：FixRes／NaFlexの共通実装と別モデル記述子。
- `src/openvlclip/backends/qwen3_vl_embedding.py⟧：2B／8Bの共通推論Backend、モデル構成別メタデータ。
- `src/openvlclip/multimodal.py⟧：新しい型付き複合入力の構造、バッチ化、検証。
- `src/openvlclip/media.py⟧等：必要な場合だけ安全なメディアデコード／前処理の抽象を追加。

Registryの`list_models()⟧／`list_pretrained()⟧／Capabilities一覧はモデル重みを読まず、ネットワークアクセスせずに動作する。`pretrained="official"⟧で各モデルの固定済み重みを選ぶ。`pretrained=None⟧拒否の既存契約を維持する。未登録checkpoint ID・revisionは拒否する。

Backend間で重複するロード／バッチ／Embedding検証コードだけ共通化し、大規模な既存Gemma／dino.txtのリファクタリングをしない。

## 5. Factory、型、モデル読み込み

既存Factory署名`model_name, pretrained, precision, device, cache_dir, output_dict, logit_scale_mode, modalities⟧を維持する。

- SigLIP 2：公式`transformers⟧実装で投影済み画像／テキスト特徴を取得する。FixResとNaFlexの前処理は分岐する。公式から読み込んだscale・biasを保持する。
- Qwen3-VL：**Embedding用公式モデル・processor・instruction組み立て・pooling**を再現する。生成用`AutoModelForCausalLM⟧の単純な最終hidden-state取得で代用しない。最後の**有効トークン**に基づくpoolingとattention maskを公式と照合する。
- `fp32⟧／`bf16⟧の受理条件はモデル・デバイス依存とする。旧BackendのFP16拒否は維持。新BackendでFP16や量子化を実装するかは実モデル検証後の別途判断とし、検証なしに「対応」と宣言しない。
- 8Bモデルはメモリ不足時に重みが半端に初期化された状態を公開せず、必要VRAM・バッチサイズ・コンテキスト上限を明確に説明する。
- `cache_dir⟧をtransformers/HF Hub/processor間で一貫して利用する。downloadを伴う操作とofflineモードの失敗をテストする。
- 原則として`safetensors⟧を優先し、任意のpickle重みを黙ってロードしない。リモートコード実行が本当に必要なら、固定リビジョン・明示的許可・レビュー済みコードのみで許可する。
- 重みはwheel/sdistに同梱しない。

## 6. 入力・前処理の契約

### 6.1 SigLIP 2 FixRes

公式processorを基準にRGB変換、Resize/Crop、正規化、テキストTokenizerを再現する。`224×224⟧の画像Tensorを標準入力とし、`model.encode_image()⟧と公式`get_image_features()⟧を同一入力で数値比較する。固定入力画像から処理した画素値も比較する。モデルに合わないDINO／GemmaのImageNet正規化を流用しない。

### 6.2 SigLIP 2 NaFlex（最優先のAPI設計注意点）

NaFlexではアスペクト比と有効patch配置が意味を持つ。公式processorが生成する`pixel_values⟧、`pixel_attention_mask⟧、`spatial_shapes⟧等の実際に必要な項目を**まとめて**Backendへ渡す。

`preprocess(image)⟧を「必ずTensorを返す」と仮定するv0.6.1の型・バッチ・画像検索実装は、既存利用者向けには維持しつつ、NaFlex用の型付き`ProcessedImage⟧／Mapping入力およびBackendに応じたcollateを追加する。仮にTensor型だけで完全に公式と一致させられる実装が見つかった場合はそれを採用してよいが、attention mask／spatial shapeを捨てる簡略化は禁止する。

- 単一画像、アスペクト比の異なる複数画像、パッチ数上限境界を検証。
- invalid mask、空バッチ、過大画像、異なるデバイス／dtypeを明確に拒否。
- 固定224cropに置き換えて「NaFlex対応」としない。
- Processorの設定`max_num_patches⟧・patch size・resize方式は`EmbeddingSpace⟧のpreprocessing IDに含める。

### 6.3 Qwen3-VL-Embedding

公式のsystem instruction、user multimodal content、chat template、image/video processor、attention mask、最終有効トークンpoolingを一致させる。

- テキストのみ、画像のみ、テキスト＋画像、動画のみ、テキスト＋動画を明示的に受理する。
- 入力がない場合は`ValueError⟧を返す。公式実装が使用する`"NULL"⟧の暗黙埋め込みを公共APIの既定動作にしない。
- 画像ファイル・PIL画像／動画ファイル・フレーム列を正式にサポートする範囲を明記する。HTTP URLの自動取得はv0.7.0の必須対象外。任意URLへの無制限通信を行わない。
- `max_length⟧、解像度、画素数、`fps⟧、`max_frames⟧は入力検証・メモリ上限を設ける。公式処理が出すピクセル予算とフレームサンプリングを再現し、値をメタデータに含める。
- v0.6.1の「動画をフレーム検索する方式」とネイティブ動画Embeddingは**別処理**として区別する。

## 7. 公開API — 既存互換と新規追加

### 7.1 既存API（MUST）

6モデルで次のメソッドとFeature shapeを正しく扱う。固定Tensor前処理を必要とする旧モデルの挙動を変更しない。

```python
from openvlclip import (
    create_model,
    create_model_and_transforms,
    get_tokenizer,
    list_models,
)

model, preprocess_train, preprocess_val = create_model_and_transforms(
    "siglip2-base", pretrained="official", precision="fp32"
)
tokens = get_tokenizer("siglip2-base")(["a red car", "a blue car"])
# 前処理・出力形状は各BackendのAPI契約に従う。
```

`encode_image(..., normalize=False, truncate_dim=None)⟧、`encode_text(..., normalize=False, truncate_dim=None)⟧は両方ともバッチの2D特徴量`[B,D]⟧を返す。Qwenは単なるtoken IDでは公式chat template／instructionの再構成が困難な場合があるため、**Qwenの既存`get_tokenizer⟧→`encode_text⟧経路は公式数値一致を確認して初めてサポートとする**。構造化されたprocessor出力が不可欠な場合は後述の`encode_texts⟧を第一級APIとして提供し、既存シグネチャに無理な型を渡して成功したように見せない。サポートしない組合せは正確な例外と代替APIを提示する。

`normalize=False⟧は各公式重みの投影・pooling直後の生特徴を返し、`True⟧はL2正規化。元モデルのAPI既定`normalize=True⟧と混同しない。QwenのMRLでは**切り詰め後にL2正規化**する。再正規化の順序を公式実装と照合する。

### 7.2 追加API：Processor-awareの第一級経路（MUST）

QwenおよびNaFlexの複雑な前処理を表現するため、後方互換のある新経路を設ける。以下は概念上の目標APIであり、最終名はPhase 0のDesign Reviewで確定する。

```python
# Tensorのほか公式processorが返すマスク等を保持できる型付き入力
prepared = preprocess_val(image)
image_features = model.encode_image(prepared, normalize=True)

# Python文字列から公式指示文とchat templateを適用（Qwen／他Backend）
text_features = model.encode_texts(
    ["A person using a drilling machine"],
    instruction="Represent the user's query for image retrieval.",
    normalize=True,
)

# Qwenの単一モーダル／複合入力を統一して埋め込む
vectors = model.encode_multimodal([
    {"text": "A drill press", "image": image},
    {"video": "sample.mp4"},
    {"text": "Safe hand position", "video": "sample.mp4"},
], normalize=True)
```

**必須契約:**
- `encode_texts(texts, *, instruction=None, normalize=False, truncate_dim=None) -> Tensor[B,D]⟧：文字列からモデル固有の正しい入力を構成。
- `encode_multimodal(items, *, normalize=False, truncate_dim=None, ...)->Tensor[B,D]⟧：Qwen専用（その他では明示的に未対応）。
- `encode_video(video, *, normalize=False, truncate_dim=None, fps=None, max_frames=None) -> Tensor[1,D]⟧：Qwenの**ネイティブ動画Embedding**。既存フレームインデックスは別API。
- 画像単独、テキスト単独、動画単独を`encode_multimodal⟧で送ったとき、対応する`encode_image⟧／`encode_texts⟧／`encode_video⟧と数値整合するよう入力共通化する。
- 入力の型、バッチ軸、出力shape、dtype、Device移動と空入力を明文化。
- `model.eval()⟧＋`torch.inference_mode()⟧を基本とする。学習グラフを返すと誤認させない。

### 7.3 QwenのInstruction／MRL（MUST）

- official instruction適用位置、句読点・スペース・chat templateを固定し、query用とdocument用のポリシーを明示する。
- Qwen 2B `D=2048⟧、8B `D=4096⟧。公式モデルカードに記載のMRLを使う。対応する短縮次元は公式実装の挙動をテストで確定する。**無条件で全整数次元を許可しない。**
- `truncate_dim=None⟧はnative次元。`truncate_dim⟧が1未満・native超・bool・非整数なら拒否。
- 2Bと8Bは短縮先が同じ2048次元でも**異なるEmbedding空間**である。
- Query/Document instructionが異なること自体は公式retrieval構成であり、単なる不一致として拒否しない。互換性検証には**同じモデルで使われるquery/documentの対応ポリシー一式**を記録する。
- デフォルトinstructionを変更すると検索スコアが変わるため、モデルのnative次元だけで互換とみなさない。

### 7.4 Logits／Zero-shot（MUST）

**SigLIP 2:** 公式の学習済み`logit_scale⟧と`logit_bias⟧を使用する。通常のCLIP形式`exp(scale) * cosine⟧だけでは不十分。`get_logits⟧のstrictモードで公式SigLIP 2出力と一致させ、sigmoidを適用する際は各候補独立の値とし、softmax確率と混同しない。`logit_scale_mode="cosine"⟧はバイアスなしのcosineのみ。

**Qwen:** 公式の学習済みCLIP式logit scale／biasがない場合、`strict⟧の`get_logits⟧は`NotImplementedError⟧、`cosine⟧でのみ正規化内積を返す。デフォルトのfactory `strict⟧でモデルロードすること自体は許可するが、未対応スコアを暗黙に推定しない。公式モデルの単純なcosineを`official scaled logits⟧と呼ばない。

**`forward⟧:** 既存の`(image_features, text_features, logit_scale)⟧契約を維持。SigLIP 2の`logit_bias⟧を別属性／明示APIとして提供し、`forward⟧の3要素だけで`get_logits⟧相当と誤認しない説明を記載。モデル固有のforwardが入力を限定する場合は分かりやすいエラーを返す。

## 8. Capabilitiesの拡張

既存キーを維持したまま、必要な新キーを**後方互換のある拡張**として追加する。推奨候補：

`video_embedding⟧、`multimodal_embedding⟧、`instruction_aware⟧、`variable_resolution⟧、`sigmoid_logits⟧。既存の`image_embedding⟧、`text_embedding⟧、`image_text_similarity⟧、`patch_embedding⟧、`text_similarity_map⟧、`mrl⟧、`selective_loading⟧は削除しない。

| モデル | image/text | MRL | ネイティブ動画 | mixed | 可変解像度 | patch/map |
| --- | --- | --- | --- | --- | --- | --- |
| EmbeddingGemma 2 | YES | YES | NO | NO | 既存どおり | NO |
| DINOv2 + dino.txt | YES | NO | NO | NO | 既存どおり | YES / YES |
| SigLIP 2 FixRes | YES | NO | NO | NO | NO | NO / NO |
| SigLIP 2 NaFlex | YES | NO | NO | NO | YES | NO / NO |
| Qwen3-VL-Embedding-2B | YES | YES | YES | YES | processor経由 | NO / NO |
| Qwen3-VL-Embedding-8B | YES | YES | YES | YES | processor経由 | NO / NO |

SigLIP 2の内部パッチ特徴やDense Predictionの存在だけで、`encode_patches()⟧／`similarity_map()⟧をTRUEにしない。v0.7.0で公式テキスト整列の数値契約を実装しない限りFALSEとする。`selective_loading⟧も実際にモダリティを分離ロードできる場合に限ってTRUE。モデルが「動画をフレーム検索できる」ことは`video_embedding=True⟧と同義でない。

Registryがcapabilities全キーを必須とする現行`freeze_capabilities⟧に合わせ、全BackendのデフォルトFALSE設定を行い、旧Backendのテストも更新する。

## 9. Image Search／Video Search／Index互換性

### 9.1 画像検索（MUST）

- `build_or_update_image_index⟧／`search_images⟧は全6モデルで動作。ただしNaFlex/Qwenのprocessor-awareな画像入力を安全にバッチ化する。
- 画像とqueryは同一のモデル固有共有空間のEmbedding。SigLIP 2とQwenを「次元が一致する」だけで混合しない。
- 内部のNative次元解決はBackend由来とし、デフォルト768への後退を禁止する。
- `verify_contents=True⟧を引き続きサポート。旧インデックスの読み込み・内容SHA-256保護・差分更新を維持する。
- `examples/image_search.py⟧に`index --verify-contents⟧を追加する（既定FALSE）。CLIのモデル選択を全登録モデルへ拡張し、Qwenのquery instructionも必要な場合は別オプションにする。

### 9.2 既存動画検索とネイティブ動画Embedding

1. **frame-search:** v0.6.1の`build_or_update_video_index⟧／`search_video⟧。複数フレームの画像Embeddingを保存し、時刻付き結果を返す。すべての画像対応モデルで使用可能にする場合は実際のprocessorバッチの対応とテストが必要。
2. **native-video:** Qwenの動画全体を1ベクトルにまとめてEmbedding化する。別のインデックス構造・検索関数（例：`build_or_update_native_video_index⟧／`search_native_video⟧）として実装。返値は動画単位のスコアであり、フレーム時刻付き検索結果ではない。

この2方式を同じファイル拡張子や同じ次元数だけで互換と判定してはならない。Qwen native-videoの前処理ポリシー（fps、max_frames、total_pixels、instruction、processor version）を保存する。既存動画検索APIの意味・結果並び順は変更しない。

### 9.3 EmbeddingSpaceメタデータ（MUST）

最低限以下を識別する。

- backend ID、checkpoint ID、固定revision
- native次元／truncate次元、MRL strategy、normalization
- official processor/tokenizer version、FixRes/NaFlex設定とpreprocessing ID
- Qwenのquery/document instructionポリシー、chat template／pooling strategy
- 入力種別（image／text／mixed／native-video／sampled-frame）
- 動画fps、max_frames、sampled-frame処理パラメータ
- model precision、storage dtype、index format version

既存`EmbeddingSpace⟧の`embedding_space_id⟧を構成するフィールドを無条件に増やすと、**保存済みv0.6.1インデックスのIDが変わる**。そのため、旧フォーマットと旧ハッシュ規則を読み取る専用パーサーを残すか、拡張用バージョン付きスキーマへ移行する。古いIDの無理な書き換えやチェック回避は禁止する。

`convert_image_index⟧／`convert_video_index⟧は、MRLとして公式にサポートされるモデル・次元のみ変換。別モデル・別入力戦略・別instruction間の変換は禁止。Qwenのtruncate→renormalizeの規則は数値検証する。非MRLのSigLIP 2やdino.txtは低次元変換を拒否する。

## 10. v0.6.1レビューでの修正（MUST）

### 10.1 `similarity_map()⟧メモリ安全性

現在のdino.txtには特徴量の「要素数」上限がある。FP32補間テンソル、normalization中間テンソル、出力map、バッチ分などを含む**ピークメモリ推定をバイト基準**に変更し、サイズ・text数・deviceを考慮する。

- 上限超えは計算前に説明付き`ValueError⟧。
- 既存の通常解像度で数値を変えない。
- GPUメモリが低い環境ではchunking/tilingも検討。ただし浮動小数の演算順序を変える場合は公式数値許容差テストを更新する根拠を明記。
- 極端な`output_size⟧、多バッチ、多テキスト、bf16/FP32をテスト。

### 10.2 dino.txt特殊Token入力検証

公開Tokenizerの文字列入力に対して`<|startoftext|>⟧／`<|endoftext|>⟧の混入を検出して拒否するか、公式通りのエスケープポリシーを明文化する。複数EOT、途中EOT、末尾不正paddingなどを誤ったEmbeddingを返さず明確に扱う。

Tokenizer→Backendの有効な通常入力と、既存公式パリティは維持する。空文字の許可／不許可も統一してテストする。

### 10.3 CLIの厳密な画像変更検出

`examples/image_search.py⟧に`--verify-contents⟧を追加し、既存の`verify_contents=True⟧へ渡す。通常モードは高速なサイズ・mtime方式のまま。READMEにコストと使用例を追加する。

- Qwenの公式リポジトリコードを取り込む必要がある場合はApache-2.0のNOTICE・出典・変更点・著作権表示とハッシュを管理する。リポジトリからコードを未検証で自動実行しない。
- HF checkpointは公式repoの固定commitで取得。`local_files_only⟧に相当するofflineモードを有効にした際はネットワークへ出ない。

## 12. テスト方針

### 12.1 ユニットテスト

- Registry listing side-effect-free、モデル名とrevision、Capabilities matrix、不正checkpoint／precision／device。
- SigLIP 2 FixResのpreprocess、token IDs、768d画像・テキスト特徴、学習済みscale/bias、logits、sigmoidとcosineの区別。
- SigLIP 2 NaFlexの縦長／横長／正方形、patch上限、padding/mask/spatial shape、batch collate、画像検索。
- Qwen 2B/8Bのプロンプトとchat template、attention mask、last-token pooling、画像／テキスト／動画／複合入力、MRL、model sizeの識別。
- Image index strict hash・旧形式・新メタデータ、frame index／native-videoの混同拒否。
- dino.txtのspecial tokens、`similarity_map⟧メモリ境界、CLI `--verify-contents⟧。
- offline、失敗時の例外、OOM、入力が不正なときに誤ったEmbeddingを返さないこと。

### 12.2 公式実モデルパリティ（公開ゲート）

各モデルの固定公式checkpointで、同じ入力・dtype・device・preprocessingの条件で参照実装と比較する。公式実装を呼ぶだけの関数を「独立したoracle」と偽装しない。OpenVLCLIP wrapperと別経路で公式APIを呼び、固定入力と参照特徴の取得方法を記録する。

| モデル | 必須パリティ対象 |
| --- | --- |
| SigLIP 2 FixRes | processor画素値、token IDs、image/text特徴、scale/bias、scaled logits、cosine |
| SigLIP 2 NaFlex | 画像のpatch/mask/spatial shape、image/text特徴、scale/bias、scaled logits |
| Qwen 2B | text/image/video/mixedのtemplate・processor・pooling・Embedding、MRL、cosine |
| Qwen 8B | 同上。少なくとも１つの検証済み大容量GPU構成で実モデルパリティ必須 |
| 既存Gemma | v0.4.0固定Embedding、MRL、selective loading |
| 既存dino.txt | 公式2048d/1024d、logits、similarity map、FP32/BF16 |

FP32基準を確立し、BF16は別の妥当な数値誤差上限を記録する。FP16や量子化を追加する場合も別基準。**未実行を「合格」と報告しない。** 8Bの実モデル検証環境を用意できず、本仕様に書いた必須機能を検証できない場合は、そのまま4モデル正式対応として公開しない。

### 12.3 CI matrix

- Windows / Linux × Python 3.12 / 3.13 / 3.14（明示的に除外しているpatch版は従来どおり除外）。
- 各optional extrasの依存解決、静的解析、通常pytest、wheel/sdistの中身検査。
- 重みをダウンロードしないCIは「unit / packaging」の成功と明示。CPU実モデルintegration、CUDA実モデルintegration、8BのGPU integrationは別ジョブ／手動または利用可能なGPUランナーで実施する。
- GitHub-hosted runnerにGPUが無いことを理由に、必要な公式実モデルパリティを省略したままリリース可としない。

## 14. `publish-pypi.yml⟧への統一（v0.7.0必須）

### 14.1 現在の状態

v0.6.1公開では`.github/workflows/publish-pypi-v0.6.0.yml⟧という**ファイル名のまま**内容をv0.6.1向けに更新し、既存Trusted Publisherを再利用した。現在の`.github/workflows/publish-pypi.yml⟧は**旧0.1.0向けのワークフロー**なので、単にファイル名を変更するだけでは危険。既存ファイルを安全な共通版へ**置換**する。

### 14.2 共通ワークフロー仕様

- ファイルは`.github/workflows/publish-pypi.yml⟧の1つ。正式リリースはtag pushで起動。`v*⟧のような粗いトリガーを許す場合でも、最初のジョブで正規表現`^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$⟧を検証する。
- `v0.7.0⟧から`0.7.0⟧を動的導出。`pyproject.toml⟧と`uv.lock⟧を照合し、公開先プロジェクト名が`openvlclip⟧であることを確認。手動dispatchやprereleaseからは公開しない。
- 同じSHAに対するmainのpush CI成功、tag commitのmain到達可能性、正確なtag ref、GitHub repository identityを検証。過去／公開済みバージョンのタグを再送しても公開しない。PyPI API照会が失敗すればfail closed。
- dino.txtライセンス確認ガードを保持。新規4モデルのライセンス出典・重み配布方針のリリースゲートを追加。
- Locked dependencies、単体テスト、Ruff、wheel／sdist内容・SHA-256検証を行い、検証済みArtifactをpublishジョブへ渡す。
- `permissions: {}⟧を既定。publishジョブ以外はread権限のみ。OIDC `id-token: write⟧はpublishジョブだけ。`pypa/gh-action-pypi-publish⟧をコミットSHA等の固定参照で利用し、Trusted Publishing・Environment `pypi⟧を維持。
- EnvironmentのRequired reviewers、tag allowlist、self-review制限、branch protectionを回避／解除しない。
- 現行の`publish-pypi-v0.6.0.yml⟧等、旧バージョン用定義は**共通ワークフローの検証・移行完了後**にmainから整理。過去のGit tag・Releaseの内容は改変しない。

新しいワークフロー名に切り替えるには、既存PyPIプロジェクト`openvlclip⟧のPublishing設定に以下のPublisherを登録する必要がある。

## 17. リスクと停止条件

- **8B VRAM／実環境:** デバイスメモリが足りず公式パリティを実測できない場合は8B正式対応と宣言せず、GPU実行環境を用意するまで正式リリースを停止する。
- **Qwen実装依存:** 配布時の任意remote code実行、商用依存・非互換ライセンス、Windowsで解決不能な必須dependencyがある場合は、安易にユーザー環境を壊さず代替方式を検討する。
- **NaFlex API:** processor情報の欠落による公式値との差異がある場合、Tensorへの強制縮約で回避せずprocessor-aware APIを完成させる。
- **Index移行:** 既存の`embedding_space_id⟧を改変して旧indexが読めなくなる方式は採用しない。
- **PyPI公開:** 未登録Trusted PublisherやEnvironmentタグ許可不足、CI不合格、外部チェックポイントのライセンス不明、PyPI到達不能時にはタグ作成／アップロードを実施しない。
- **数値一致:** 不具合を隠すための許容誤差拡大、テストskipへの置換、偽のベンチマーク値の記載を禁止する。
